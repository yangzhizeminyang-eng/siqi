# Stitch 中文界面生成提示词

## 1. 使用说明

本文档基于 `07-ui-high-fidelity.md` 编写，用于指导 Stitch 生成司契（Siqi）的中文 Web 管理台。

推荐使用顺序：

1. 先使用“总控提示词”建立统一 App Shell 和设计系统。
2. 再按页面提示词逐页生成。
3. 每次生成新页面时，要求保持已有导航、颜色、字体和组件样式。
4. 最后使用“统一检查提示词”检查中文、状态、权限和布局。

## 2. 总控提示词

```text
请设计一个司契（Siqi）的桌面 Web 管理台，产品名称为“司契（Siqi）”。

这是研发流程控制台，不是营销网站。不要使用大幅 Hero、宣传海报、渐变背景、装饰性光晕、过多插画、消费级 App 风格或卡片套卡片布局。

【语言要求】
- 所有页面可见 UI 文案必须使用简体中文。
- 菜单、按钮、页面标题、表格表头、状态标签、空状态、错误提示、确认弹窗全部使用中文。
- 技术标识、文件路径、Commit SHA、接口路径、命令和代码内容可以保留英文。
- 不要出现英文菜单、英文按钮、英文状态标签或英文空状态文案。

【产品流程】
开发者创建任务 -> 拉取 Gitee Issue 快照 -> 复用或创建仓库级代码索引 -> 使用 LlamaIndex + Milvus 检索代码上下文 -> AI 分析问题 -> 生成修改计划 -> 人工审批 -> 生成 Diff -> Docker 隔离执行测试 -> 生成 PR 描述 -> 任务完成。

【统一 App Shell】
- 左侧固定导航宽度 240px。
- 顶部工具栏高度 64px。
- 主内容区域使用 12 列栅格，左右内边距 24px，栅格间距 16px。
- 默认桌面画布宽度 1440px，最小支持宽度 1280px。
- 1280px 以下自动收起右侧信息栏，并改为右侧抽屉。
- 页面背景色 #F7F8FA，主内容区域白色，边框 #E5E7EB。
- 主色 #2563EB，成功色 #16A34A，警告色 #F59E0B，危险色 #DC2626，信息色 #0EA5E9。
- 圆角统一 8px，不使用过度圆润的装饰性卡片。
- 中文字体使用 PingFang SC 或 Microsoft YaHei。
- 页面标题 20-24px，分区标题 16-18px，正文 14px，辅助说明 12px。
- 标题字重 600，正文字重 400，正文行高 1.5。
- 代码、Diff、Commit SHA、命令和日志使用 JetBrains Mono 或 Consolas。

【一级导航】
工作台、任务列表、审批中心、任务回放、Diff 审核、索引管理、项目配置。

【任务状态中文】
已创建、Issue 已拉取、代码上下文已索引、AI 分析完成、修改计划已生成、等待人工审批、审批通过、审批拒绝、Diff 已生成、测试完成、PR 描述已生成、任务完成、任务失败、用户主动取消。

【通用状态】
每个核心页面都要有加载中、空状态、成功态、错误态和权限不足态。
空状态必须有中文说明和下一步按钮。
危险操作必须有中文确认弹窗。
所有布局必须避免文字溢出、按钮重叠、表格截断和小屏错位。

请生成真实可用的企业研发管理台界面，不要只生成装饰性概念稿。
```

## 3. 工作台首页

```text
基于已有的“司契（Siqi）”设计系统，生成“工作台”首页。

页面目标：让用户快速看到任务总览、待审批任务、高风险任务、执行中任务和最近动态。

页面结构：
- 顶部显示项目选择器、全局搜索、通知铃铛、当前用户。
- 内容区顶部放四个摘要指标：风险任务、待审批、执行中、已完成。
- 中部放最近任务表格，列为：任务名称、Issue、仓库、状态、风险、审批人、更新时间、操作。
- 下部放任务趋势图、风险分布和最近日志摘要。
- 待审批、高风险、超过 24 小时未处理的任务使用明显但克制的高亮。

交互：
- 点击“创建任务”进入创建任务页。
- 点击待审批指标进入审批中心。
- 点击任务行进入任务详情。
- 通知铃铛显示未读待办数量。

请同时生成有数据态、加载态、空状态和错误态。
所有可见文字必须使用简体中文。
```

## 4. 任务列表与创建任务

```text
请生成“任务列表”和“创建任务”两个页面，并保持同一套 App Shell、导航、表格和表单样式。

【任务列表页】
- 顶部筛选：项目、状态、风险等级、关键字、时间范围。
- 操作按钮：创建任务、刷新、批量操作。
- 表格列：任务名称、Issue、仓库、状态、风险、审批人、更新时间、操作。
- 选中任务后打开右侧摘要抽屉，展示任务摘要、当前阶段、最近事件和快捷操作。
- 可取消状态显示“取消任务”，终态不显示取消按钮。

【创建任务页】
- 表单字段：项目、仓库、Issue ID、基线分支、测试命令。
- 工作分支由系统自动生成，只读展示，字段名为“预计工作分支”。
- project、repository、issue_id、base_branch 为必填项。
- Issue 不存在、无权限、Token 过期时显示明确中文错误。
- 同一 Issue 存在未结束任务时，提示“该 Issue 已有进行中的任务”，并提供“查看已有任务”。
- 右侧说明展示：可用索引会复用，索引缺失或过期时需要创建或重建。

按钮文案固定使用：创建任务、取消、刷新、批量操作、查看已有任务。
```

## 5. 任务详情页

```text
请生成“任务详情”页面，这是平台最核心的工作页面。

采用三栏布局，比例约为 28% / 47% / 25%：
- 左栏：Issue 信息，包括标题、正文、评论、标签、基线分支、工作分支。
- 中栏：AI 分析、问题确认、修改计划。
- 右栏：代码上下文、RAG 相似度、审批记录、最近执行事件、Diff/测试/PR 入口。

顶部显示任务标题、中文状态标签、风险等级、仓库、审批人和操作按钮。

问题确认区：
- 当 AI 分析产生待确认问题时，必须显示在修改计划上方。
- 每个问题显示问题内容、回答输入框和回答状态。
- 提供“保存回答”“跳过问题”“重新生成计划”。

状态交互：
- 审批通过前，“生成 Diff”按钮禁用，并显示中文原因。
- 当前用户有审批权限时，显示“打开审批”入口。
- 可取消状态显示“取消任务”，点击后显示中文二次确认弹窗。
- 模拟 Diff、模拟测试摘要、模拟 PR 草稿必须显示醒目的“演示兜底”标签。

请生成真实数据态、待回答态、加载态、失败态和权限不足态。
```

## 6. 审批中心

```text
请生成“审批中心”页面，用于审批人审核 AI 生成的修改计划。

页面结构：
- 顶部显示“待审批列表”和站内待办数量。
- 表格列：任务名称、风险等级、仓库、提交人、审批人、提交时间、催办状态、操作。
- 待审批任务按当前用户权限过滤。
- 项目默认审批人需要明确展示。
- 超过 24 小时未处理的任务显示“可催办”入口。

审批详情采用三栏布局，比例约为 30% / 40% / 30%：
- 左栏：计划摘要。
- 中栏：文件范围和变更类型。
- 右栏：风险提示、风险阈值说明和审批历史。

当风险达到项目风险阈值时：
- 顶部显示红色或橙红色强提示条。
- 显示“该任务达到项目风险阈值”。
- 审批意见输入框变为必填。

底部固定三个中文操作按钮：
“通过”“拒绝”“要求重写”。
拒绝和要求重写时，审批意见必须填写。
所有确认弹窗、校验提示和成功提示必须使用中文。
```

## 7. 任务回放页

```text
请生成“任务回放”页面，用时间线展示 Agent 任务的完整执行过程。

左侧为任务时间线，右侧为步骤详情。

时间线必须包含：
任务创建、Issue 拉取、RAG 索引、RAG 检索、AI 分析、问题确认、计划生成、审批通过、Diff 生成、测试执行、PR 描述生成、重试、用户主动取消、任务完成、任务失败。

右侧步骤详情根据选中节点展示：
- 节点输入。
- 节点输出。
- 工具调用记录。
- 检索 Query、Top-K、来源文件、行号、Commit SHA、相似度。
- 测试命令、耗时、退出码、stdout、stderr。
- Diff、测试和 PR 产物。
- 演示兜底标签。

要求：
- 时间线支持折叠、展开和跳转。
- 失败步骤显示失败原因和重试入口。
- 用户主动取消显示取消人、取消时间和取消前状态。
- 所有节点状态使用中文标签。
```

## 8. Diff 审核页

```text
请生成“Diff 审核”页面，用于审查 AI 生成的代码修改。

页面布局：
- 顶部显示文件统计、修改行数、风险等级、当前任务和计划版本。
- 左侧文件列表固定宽度约 280px，可搜索和筛选。
- 右侧为主要 Diff 对比区域，展示原始代码和修改后代码。
- 新增、删除、修改使用清晰的语义颜色。
- 文件路径、Commit SHA 和代码内容使用等宽字体。
- 底部固定审阅意见输入区，包含文本框和“提交审阅意见”按钮。

要求：
- 默认打开第一个变更文件。
- 支持切换文件和复制代码。
- 模拟 Diff 必须显示“演示兜底”标签。
- 审批前不得显示可执行的 Diff 生成操作。
- 所有按钮和提示使用中文。
```

## 9. 索引管理页

```text
请生成“索引管理”页面，用于管理员和研发负责人管理仓库级代码索引。

顶部显示项目筛选、仓库筛选，以及“创建索引”“重建索引”“重试”操作。

主表格列：
仓库、分支、Commit SHA、状态、文件数、切片数、复用状态、失败原因、操作。

状态在界面必须使用中文：
待处理、同步中、解析中、向量生成中、写入中、索引完成、索引失败。

右侧详情抽屉显示：
- 索引版本。
- LlamaIndex 解析进度。
- Milvus Collection。
- 最近检索任务。
- 错误日志。

规则：
- Commit 匹配且索引完成时显示“可复用”。
- 过期索引显示“仅可人工查看，不允许自动 Diff”。
- 失败索引显示失败原因和“重试”。
- 创建、重建、重试都需要中文确认弹窗和审计提示。
```

## 10. 项目配置页

```text
请生成“项目配置”页面，包含仓库配置、模型配置、测试命令、审批策略和安全策略。

表单字段：

- 仓库地址。
- 默认分支。
- 测试命令。
- 命令白名单。
- 风险等级阈值。
- 默认审批人。
- 审批模式。
- 模型选择。

安全要求：
- Gitee Token 和模型 API Key 不允许明文回显。

- 更新密钥使用“重新填写”。
- 保存前显示会写入审计记录的中文提示。
- 高风险配置项显示警告提示。

提供“保存”“保存草稿”“重置”三个中文操作。
```

## 11. 统一检查提示词

```text
请检查当前生成的所有页面是否符合以下要求，并直接修正问题：

1. 所有页面可见文案必须是简体中文。
2. 不得出现英文菜单、英文按钮或英文状态标签。
3. 一级导航必须完整包含：工作台、任务列表、审批中心、任务回放、Diff 审核、索引管理、项目配置。
4. 必须存在创建任务页和索引管理页。
5. 任务详情必须包含问题确认区。
6. 必须支持用户主动取消任务，并显示中文确认弹窗。
7. 审批中心必须包含默认审批人、站内待办、24 小时催办和风险阈值强提示。
8. Diff 审核必须包含审阅意见输入和“提交审阅意见”。
9. 模拟产物必须明确标记为“演示兜底”。
10. Token 和模型 API Key 不得明文显示。
11. 任务回放必须包含 RAG 检索、测试执行、PR 描述生成、重试和取消事件。
12. 所有状态标签必须使用中文展示。
13. 检查 1280px 宽度下是否有文字溢出、按钮重叠、表格截断和抽屉遮挡。
14. 检查加载、空、错误和权限不足状态是否存在。
```
