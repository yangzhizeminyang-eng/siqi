## 2. 迁移 / schema 边界

- 迁移策略**前向-only，禁止 downgrade**。
- DB 领先（旧镜像读新 schema）→ **迁移层兼容启动**（不升级/不降级），但**非应用全局只读**：旧应用写新表/列由调用方评估，本包不提供统一写入门禁。
- `alembic_version` 多行、多 head、unknown、无祖先关系（分叉）→ 一律 fail-closed 阻断。

## 3. 合规与网络边界

- 中国大陆公网依赖 **ICP 备案**；备案未生效期间 DNSPod 可能拦截 80/443（历史 §16–18）。
- 备案/运营商路径导致的公网差异性（如个别源网络 reset）不计入可用性承诺。
- 安全组需仅放行公网 80/443（+团队 8080 按需）；DB/Redis/Milvus 不公网。

## 4. 容量与高可用边界

- 单区单机私有化；多副本 backend + frontend 轮询自愈，但**不提供跨区/跨地域多活容灾**。
- 极端承载未压测：容量上限（并发/数据量/RAG 切片）为后续商业协议而非本文档承诺。
- apponly 栈无 worker/Milvus：长任务走 eager、RAG 无向量（`USE_MILVUS=false`）；如需异步/向量检索须启用相应栈并重新验收。

## 5. 数据与安全边界

- 演示/播种数据已脱敏；生产机密（JWT/口令/私钥/Token）不入库、不写入本交付包。
- 备份 `RPO` 默认 ≤24h（每日），可调频；`RTO` 小库 ~4s，目标 ≤30min（含恢复演练）。
- 安全基线项以 `security-scan.sh` 脱敏输出为准；如实未覆盖项不得默认承诺。
