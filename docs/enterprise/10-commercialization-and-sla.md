# 企业版商业化、试点与 SLA

## 1. 企业试点目标

先用一个真实研发团队、一个主要项目和一套脱敏演示数据完成“需求 -> RAG -> 方案 -> 审批 -> 变更 -> 测试 -> PR -> 审计”的闭环，再扩大租户和项目规模。

## 2. 试点交付流程

```mermaid
flowchart LR
    A[客户需求和环境调研] --> B[部署与安全配置]
    B --> C[租户、组织、成员初始化]
    C --> D[绑定示范仓库并构建索引]
    D --> E[演示真实研发任务闭环]
    E --> F[执行安全、RAG 和性能验收]
    F --> G[提交问题清单和修复记录]
    G --> H[客户签署试点验收]
    H --> I[进入正式交付或扩容评估]
```

## 3. 试点套餐范围

| 项目 | 试点交付 |
| --- | --- |
| 租户 | 1 个企业租户 |
| 组织 | 至少 2 个组织或部门 |
| 项目 | 至少 2 个项目，验证隔离 |
| 用户 | 管理员、审批人、开发者、审计员 |
| 仓库 | 至少 1 个真实仓库和 1 个隔离验证仓库 |
| RAG | Hybrid、过滤、freshness、评测报告 |
| Agent | 分析、规划、变更、审查、测试和 PR 门禁 |
| 运维 | HTTPS、备份、监控、升级和回滚演练 |

## 4. 配额设计

第一阶段不实现计费，但应预留租户配额：

- 并发 Agent 任务数；
- 每日模型 Token；
- 每日 RAG 查询量；
- 索引仓库数量和数据量；
- Runner CPU、内存和执行时长；
- 审计导出频率和文件大小。

超过配额时返回明确错误，不得静默降级或绕过限制。

## 5. SLA 指标建议

| 指标 | 试点建议 |
| --- | --- |
| 平台月度可用性 | 99.5% 起步 |
| 核心 API P95 | 小于 500ms，不含长任务 |
| RAG 查询 P95 | 小于 5s，依模型配置调整 |
| 任务创建响应 | 小于 1s，返回任务 ID |
| 故障响应 | 关键故障 30 分钟内确认 |
| RPO | 24 小时起步 |
| RTO | 4 小时起步 |

正式 SLA 需要依据客户环境、部署形态、依赖服务和支持级别签署，不能仅用产品文档承诺。

## 6. 客户交付包

- 版本说明和变更记录；
- Docker Compose 或 Kubernetes 部署包；
- 环境变量模板和密钥注入说明；
- 数据库迁移和回滚说明；
- 管理员初始化手册；
- 用户操作手册；
- 监控、告警和备份恢复手册；
- 安全加固清单；
- 测试报告、验收报告和真实运行截图；
- 已知限制和后续路线图。

## 7. 商业化后续

企业版稳定后再建设：

- 计费、合同和用量报表；
- 多副本和高可用；
- Kubernetes、多云和灾备；
- SAML、SCIM、ABAC、DLP；
- 插件市场和外部系统连接器；
- 行业合规认证和客户专属模型。
