## 4. 功能说明

本次完成 Vue 3 前端工程基线，并将 Stitch 参考稿中的页面结构整理成统一的企业级控制台体验。

已覆盖页面：

- 登录；
- 工作台；
- 任务列表；
- 创建任务；
- 任务详情；
- 审批中心；
- 任务回放；
- Diff 审核；
- 索引管理；
- 项目配置。

核心交互：

- 任务列表搜索、状态筛选和右侧摘要抽屉；
- 创建任务必填校验和工作分支预览；
- 任务详情阶段轨迹、问题确认和计划展示；
- 审批中心高风险意见必填；
- 回放页面时间线节点切换；
- Diff 文件切换、前后对比和复制 Patch；
- 索引重建二次确认；
- 配置页按模块切换，密钥不回显。

## 5. 遇到的问题

1. Stitch 参考稿中存在旧品牌、英文残留和内部复审词，不能直接复刻到产品界面。
2. Diff 页面曾在参考稿中使用独立导航壳，容易破坏企业控制台的一致性。
3. Windows 工作区路径包含特殊连字符，npm 默认 `.cmd` 脚本会把 `vue-tsc` 解析到错误路径。

## 6. 解决方案

1. 统一产品名称为“司契（Siqi）”（沿革：原“研发协作平台”，2026-10-12 定名「弈谱（Yipu）」并同日更名「司契（Siqi）」，见 [`品牌定名方案-司契.md`](../品牌定名方案-司契.md)），所有页面共享同一套 App Shell。
2. 用任务阶段轨迹作为产品识别元素，强化 Issue、检索、分析、审批、Diff、测试、完成的流程感。
3. 设计系统采用浅色工作台、低对比边框、语义状态色和等宽技术区，避免营销式页面。
4. `package.json` 改为通过 Node 直接调用 `vue-tsc` 和 `vite`，绕开 Windows `.cmd` 路径问题。
5. 将 Mock 数据集中在 Pinia store，为后续真实 FastAPI 接口替换留出边界。

## 8. 复盘

这次主要练到了从参考稿抽象出产品级前端基线的能力：不能只看页面像不像，而要看流程、状态、权限、审计和后端接口边界是否能接住。

做得比较好的地方：

- 先把页面壳和状态模型定住，再做页面细节；
- 没有照搬参考稿里的旧品牌和内部复审词；
- 把构建脚本问题一起收掉，避免后续重复踩坑。
