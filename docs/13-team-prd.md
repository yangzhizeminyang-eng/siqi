## 1. 文档定位

本文档描述 MVP 完成后的团队版增量需求。团队版不推翻 MVP 主流程，而是在“单人可控研发闭环”基础上补齐多人协作、审批分配、任务可见性和团队级配置能力。

## 2. 团队版目标

团队版要证明平台可以服务一个小型研发团队，而不是只服务单个演示用户。

核心目标：

- 多成员共同使用同一个项目空间。
- 任务可以分配负责人、审批人和关注人。
- 审批、通知、评论和回放形成团队协作闭环。
- 项目级配置可以由管理员统一管理。

## 3. 新增角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 团队管理员 | 管理团队成员、项目配置和默认审批规则 | 成员管理、配置管理、审计查看 |
| 项目负责人 | 负责项目内任务推进和审批策略 | 查看项目全部任务、指定审批人 |
| 开发者 | 创建和跟进自己的 Agent 任务 | 创建任务、回答问题、查看结果 |
| 审批人 | 审核修改计划和高风险操作 | 审批、拒绝、要求重写 |
| 观察者 | 只读查看任务与回放 | 查看任务、查看回放 |

## 4. 新增用户故事

| 编号 | 用户故事 | 验收标准 |
| --- | --- | --- |
| TEAM-US-01 | 作为团队管理员，我可以邀请成员加入项目 | 成员可被邀请、移除、停用 |
| TEAM-US-02 | 作为项目负责人，我可以为任务指定审批人 | 待审批列表只展示当前用户可审批任务 |
| TEAM-US-03 | 作为开发者，我可以在任务详情里评论和补充上下文 | 评论写入任务事件，可在回放中追踪 |
| TEAM-US-04 | 作为审批人，我可以收到待审批提醒和催办 | 站内通知可见，超过 24 小时可催办 |
| TEAM-US-05 | 作为观察者，我只能查看任务，不能触发执行 | 操作按钮按权限隐藏或禁用 |

## 5. 新增功能范围

### 5.1 成员管理

- 邀请成员加入团队。
- 设置成员角色。
- 停用成员账号。
- 查看成员最近操作记录。

### 5.2 任务协作

- 任务负责人。
- 审批人。
- 关注人。
- 任务评论。
- @成员提醒。

### 5.3 团队通知

- 站内通知。
- 待审批提醒。
- 超时催办。
- 任务失败提醒。

### 5.4 团队级配置

- 默认审批人。
- 默认风险阈值。
- 默认测试命令。
- 默认仓库索引策略。

## 6. 不进入团队版范围

- 多租户计费。
- 企业 SSO。
- 私有化交付。
- 跨组织数据隔离。
- 高可用部署。

这些能力进入企业版增量文档。

## 7. 团队版验收

- 至少 3 个成员可以在同一项目内协作。
- 不同角色看到的页面操作不同。
- 待审批任务能按审批人正确过滤。
- 评论、审批、催办、失败提醒能写入事件流。
- 团队配置变更能写入审计日志。
