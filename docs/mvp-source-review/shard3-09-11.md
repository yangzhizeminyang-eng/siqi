## 09-modification-plan（修改计划 DEV-009）

### 1. 功能目标与范围

将 AI 分析结论转化为可审批的结构化修改计划。核心链路：任务完成 AI 分析（ANALYZED 态）→ 通过上下文 fresh 门禁与审批人前置校验 → 调用 DeepSeek 生成计划草稿（失败回退规则生成）→ 规则侧重算风险等级 → 落库并将任务推入 WAITING_APPROVAL。

**范围**：计划生成、版本化列表/详情、审批人要求重写（rewrite）、计划审批通过/拒绝。
**不做**：模型不参与风险决策（风险始终由规则重算）；不做会签/多级审批；不做计划内容的人工逐字段编辑（仅 rewrite 整体重生成）。

### 3. 数据模型 / 状态机

**ModificationPlan**（main.py:408-432）完整字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | str | PLAN-{task_suffix}-{version} |
| task_id | str | 所属任务 |
| version | int | 版本号，从 1 递增 |
| goal | str | 计划目标 |
| file_scope | list[PlanFileScope] | 文件范围 |
| steps | list[PlanStep] | 执行步骤 |
| risk_level | RiskThreshold | low/medium/high（规则重算） |
| risk_reason | str | 风险判定原因 |
| test_suggestions | list[str] | 测试建议 |
| assumptions | list[str] | 假设前提 |
| rollback_plan | list[str] | 回滚方案 |
| generated_from_analysis_revision | int | 来源分析版本 |
| generated_from_context_ids | list[str] | 来源上下文 chunk ID |
| provider | Literal["deepseek","mvp-rule-based"] | 生成来源 |
| status | PlanStatus | DRAFT/WAITING_APPROVAL/APPROVED/REJECTED/SUPERSEDED |
| risk_adjust_reason | str\|None | 审批调整风险原因 |
| risk_adjust_from | RiskThreshold\|None | 调整前风险等级 |
| approved_by_id / approved_by_name / approved_at / approval_comment | - | 审批记录 |
| created_by / created_by_name / created_at | - | 创建审计 |

**PlanFileScope**（main.py:390）：file_path, change_type(modify/add/delete/unknown), reason, risk_hint。
**PlanStep**（main.py:397）：order, title, description, target_files, risk_hint。

**calculate_plan_risk 规则**（main.py:1916-1947）：
1. **delete → high**：file_scope 中任一 change_type=="delete"，直接返回 high。
2. **高风险关键词 → high**：scope_text 命中 PLAN_HIGH_KEYWORDS（含 security/权限/鉴权/支付/资金/删除/生产/secret/token/漏洞/数据库迁移/migration/ddl/schema/密钥/api_key/审批/approval/rbac/审计），返回 high。
3. **中风险关键词或 ≥4 文件 → medium**：命中 PLAN_MEDIUM_KEYWORDS（状态机/跨模块/兼容协议/重构/协议）或 file_scope 长度 ≥4，返回 medium。
4. **否则 low**。

**P2 遗留核实 — 风险重算是否仍混入 Issue 全文**：
当前 `calculate_plan_risk` 的 scope_text（main.py:1928-1935）由以下部分拼接：`scope.file_path` + `scope.reason` + `scope.risk_hint` + `step.title` + `step.description` + `code_contexts[].content`。**不包含 `task_snapshot_text(task)`（Issue 标题+正文+评论+标签）**。对比 `generate_mock_plan`（main.py:1804）中 `text = task_snapshot_text(task)` 仅用于 change_type 推断（delete 判断），不进入风险重算的 scope_text。
**结论：P2 已修复。** 测试 `test_plan_risk_does_not_overreact_to_issue_text_when_plan_is_neutral`（通过）验证了中性计划不会因 Issue 文本中的高风险词被误判为 high。

**PlanStatus 状态迁移**：
```
(生成) → WAITING_APPROVAL ──approve──→ APPROVED
                      ├──reject──→ REJECTED（任务 FAILED）
                      └──rewrite──→ 旧版 SUPERSEDED，新版 WAITING_APPROVAL
```

## 10-approval-module（审批 DEV-010）

### 1. 功能目标与范围

为修改计划提供单审批人制的审批工作流。核心：审批人队列（按 owner 过滤）、审批人指派/改派、归属校验（仅被指派人可操作，admin 兜底）、审批通过/拒绝/要求重写、24h 逾期前端提示、审计事件留痕。

**范围**：待审批队列、审批候选人列表、审批人指派、计划审批动作的归属校验与审计。
**不做**：会签/多级审批/审批链；后端不自动处理逾期（仅前端展示提示）；不做审批 SLA 升级。

### 2. 后端接口与关键代码

| 方法 | 路径 | main.py 行号 | 权限 | 核心逻辑 |
|------|------|-------------|------|----------|
| GET | `/api/approvals/pending` | 4173 | approval:view | 待审批队列：status==WAITING_APPROVAL；非 admin 过滤 approval_owner_id==user.id；按 updated_at 倒序 |
| GET | `/api/approvals/candidates` | 4184 | approval:assign | 候选人列表：role in {admin, approver}，返回 public_user 脱敏信息 |
