# UI 线框与高保真设计文档

## 1. 文档目标

这份文档用于指导 Stitch 生成司契（Siqi）的界面。

它不是 PRD，也不是接口文档，而是直接回答下面这些问题：

- 页面长什么样
- 每个区域放什么
- 组件怎么排布
- 状态怎么表现
- 交互怎么走
- 哪些地方需要保留线框结构

本项目的 UI 风格应偏向企业研发控制台，而不是营销页或消费级 App。

MVP 以桌面 Web 管理台为主，移动端只保留后续扩展位，不进入本版高保真范围。

## 2. 设计原则

1. 信息密度高，但结构清晰。
2. 以任务、审批、日志、Diff、回放为核心，不做花哨装饰。
3. 页面要适合研发人员快速扫描和比较。
4. 关键操作必须显眼，非关键内容可折叠。
5. 所有状态都必须有明确反馈：加载、空、成功、失败、审批中、执行中。
6. 页面文本尽量短，术语一致，避免宣传口吻。

## 3. 视觉规范

### 3.1 整体风格

- 关键词：企业级、克制、清晰、可扫读、可追踪
- 参考气质：研发工作台、任务中台、审计控制台
- 避免：大横幅、营销海报风、渐变背景卡片、过多圆角装饰
- 所有页面可见 UI 文案必须使用简体中文。
- 技术标识、路径、Commit SHA、接口路径和代码内容可以保留英文，并使用等宽字体。
- 不生成英文按钮、英文菜单、英文状态标签或英文空状态文案。

### 3.2 颜色建议

建议采用中性浅色界面为主，语义色辅助识别：

| 类型 | 建议 |
| --- | --- |
| 页面背景 | `#F7F8FA` |
| 主内容卡片 | `#FFFFFF` |
| 主文字 | `#1F2937` |
| 次文字 | `#6B7280` |
| 边框 | `#E5E7EB` |
| 主色 | `#2563EB` |
| 成功 | `#16A34A` |
| 警告 | `#F59E0B` |
| 危险 | `#DC2626` |
| 信息 | `#0EA5E9` |

### 3.3 字体与尺寸

- 中文字体：PingFang SC / Microsoft YaHei
- 英文字体：Inter / System UI
- 代码、Diff、Commit SHA、命令和日志：JetBrains Mono / Consolas
- 页面主标题：20-24px
- 分区标题：16-18px
- 正文：14px
- 辅助说明：12px
- 正文行高：1.5
- 表格行高：44-48px
- 标题字重：600
- 正文字重：400
- 圆角：8px
- 页面间距：16px / 24px
- 卡片间距：12px / 16px

### 3.4 布局约定

- 桌面端主宽度：1440px 左右
- 左侧导航：240px
- 顶栏：64px
- 主内容区：弹性布局
- 右侧信息栏：320px，可折叠
- 推荐最小支持宽度：1280px
- 1280px 以下自动收起右侧信息栏，三栏页面改为“主内容 + 抽屉”
- 1024px 以下不作为 MVP 高保真目标，只保证内容不重叠、不被截断
- 页面主体使用 12 列栅格，内容区左右内边距 24px，栅格间距 16px
- 任务详情页三栏比例建议为 28% / 47% / 25%
- 审批中心页三栏比例建议为 30% / 40% / 30%
- Diff 审核页文件列表宽度 280px，Diff 主区域占剩余空间
- 索引管理页表格占主区域，详情使用右侧 360px 抽屉

### 3.5 页面状态规格

| 状态 | 视觉要求 |
| --- | --- |
| 加载中 | 使用局部骨架屏或加载指示器，保留页面结构，不让布局跳动 |
| 空状态 | 使用简洁图标、中文说明和明确的下一步按钮 |
| 成功态 | 展示真实数据、状态标签和最近更新时间 |
| 错误态 | 展示错误原因、重试按钮和必要的人工处理入口 |
| 权限不足态 | 展示“暂无权限查看此页面”，不展示敏感数据 |
| 危险操作确认 | 使用确认弹窗，说明影响范围、操作者和不可逆后果 |

各页面至少提供以下空状态引导：

| 页面 | 空状态文案 | 主操作 |
| --- | --- | --- |
| 工作台 | 当前项目还没有任务 | 创建任务 |
| 任务列表 | 暂无符合条件的任务 | 清除筛选 |
| 审批中心 | 当前没有待审批任务 | 查看全部任务 |
| 任务回放 | 暂无可回放记录 | 返回任务详情 |
| Diff 审核 | 审批通过后才会生成 Diff | 返回任务详情 |
| 索引管理 | 当前项目还没有仓库索引 | 创建索引 |
| 项目配置 | 尚未完成项目配置 | 开始配置 |

## 5. 页面线框图

### 5.1 登录页

页面目标：快速登录系统，进入任务工作台。

```text
+--------------------------------------------------------------+
| 左侧品牌区                    | 右侧登录卡片                 |
| - 项目名称                    | - 标题                      |
| - 一句话定位                  | - 会话提示                  |
| - 会话/权限说明               | - 账号输入                  |
| - 角色收口标签               | - 密码输入                  |
|                               | - 保持登录 / 忘记密码       |
+--------------------------------------------------------------+
```

页面要求：

- 左侧保持克制，但要保留会话、权限和退出的关键信息，不放营销式长文案；
- 右侧登录卡片居中，字段简洁，并补充真实会话提示；
- 不保留空的第三方接入位，避免看起来像功能已存在但实际未接通。

### 5.2 工作台首页

页面目标：让用户一眼看到任务总览、待审批项和最近动态。

```text
+----------------------------------------------------------------------------------+
| 顶栏：项目选择 / 搜索 / 通知 / 用户                                               |
+---------------------+------------------------------------------------------------+
| 左侧导航            | 主内容区                                                   |
| - 工作台            | [风险总览] [待审批] [执行中] [已完成]                        |
| - 任务列表          | ---------------------------------------------------------- |
| - 审批中心          | [最近任务表格]                                             |
| - 任务回放          | ---------------------------------------------------------- |
| - Diff 审核         | [任务趋势图 / 风险分布]                                    |
| - 索引管理          | ---------------------------------------------------------- |
| - 项目配置          | [最近日志摘要]                                             |
|                     | ---------------------------------------------------------- |
+---------------------+------------------------------------------------------------+
```

页面要求：

- 首页不要做成营销式 hero。
- 顶部先放四个摘要指标卡。
- 中间是最近任务表格。
- 底部可以放任务趋势和日志摘要。
- 待审批、高风险、超过 24 小时未处理的任务要有高亮入口。

### 5.3 任务列表页

页面目标：快速查看所有 Agent 任务的状态、来源和进度。

```text
+----------------------------------------------------------------------------------+
| 筛选栏：项目 / 状态 / 风险等级 / 关键字 / 时间范围                                |
| [创建任务] [刷新] [批量操作]                                                     |
+----------------------------------------------------------------------------------+
| 表格：任务名称 | Issue | 仓库 | 状态 | 风险 | 审批人 | 更新时间 | 操作           |
+----------------------------------------------------------------------------------+
| 右侧抽屉（选中任务后）                                                           |
| - 任务摘要                                                                      |
| - 当前阶段                                                                      |
| - 最近事件                                                                      |
| - 快捷操作                                                                      |
+----------------------------------------------------------------------------------+
```

页面要求：

- 任务列表要支持密集展示。
- 状态、风险、审批状态要使用标签。
- 选中行后右侧抽屉显示任务概览。
- “创建任务”按钮进入独立创建任务页。
- 可取消任务在操作列显示“取消”，终态任务不显示取消。

### 5.4 创建任务页

页面目标：让开发者从 Gitee Issue 创建 Agent 任务，并明确基线分支和测试命令。

```text
+----------------------------------------------------------------------------------+
| 顶部：创建任务 / 所属项目 / 返回任务列表                                         |
+----------------------------------------------------------------------------------+
| 表单区                                                                           |
| - 项目选择                                                                       |
| - 仓库选择                                                                       |
| - Issue ID                                                                       |
| - 基线分支 base_branch                                                           |
| - 测试命令                                                                       |
| - 模型 Provider                                                                  |
| - 预计工作分支：系统自动生成，只读展示                                           |
| [创建任务] [取消]                                                                |
+----------------------------------------------------------------------------------+
| 右侧说明                                                                         |
| - 工作分支由系统根据 Issue 和任务版本生成                                        |
| - 已有可用索引会直接复用                                                         |
| - 索引缺失或过期时会提示创建 / 重建                                              |
+----------------------------------------------------------------------------------+
```

页面要求：

- `project`、`repository`、`issue_id`、`base_branch` 为必填。
- `branch_name` 只读展示，不允许用户手填。
- Issue 不存在、无权限、Token 过期时要展示明确错误。
- 同一 Issue 有未结束任务时，提示跳转已有任务。

### 5.5 任务详情页

页面目标：集中展示 Issue、AI 分析、相关代码、修改计划。

```text
+----------------------------------------------------------------------------------+
| 顶部：任务标题 / 状态 / 风险 / 仓库 / 审批人 / 操作按钮                         |
+---------------------------+-------------------------------+----------------------+
| 左栏：Issue 信息          | 中栏：AI 分析 / 问题确认 / 计划 | 右栏：上下文与日志  |
| - 标题                    | - 问题摘要                    | - 相关文件            |
| - 正文                    | - 任务类型                    | - 引用片段            |
| - 评论                    | - 影响模块                    | - RAG 相似度          |
| - 标签                    | - 不确定项                    | - 审批记录            |
| - 基线分支                | - 待确认问题 / 回答输入       | - 最近执行事件        |
| - 工作分支                | - 修改计划                    | - Diff / 测试 / PR 入口 |
+---------------------------+-------------------------------+----------------------+
```

页面要求：

- AI 分析部分要放在最显眼的位置。
- 如果存在待确认问题，必须在计划区域上方展示“问题确认”区。
- 问题确认支持回答、跳过、保存，并能触发重新生成计划。
- 修改计划必须结构化展示。
- 相关文件点击后能看上下文片段。
- 当前用户具备审批权限时，可从任务详情打开审批操作抽屉或跳转审批中心。
- 审批通过前，生成 Diff 按钮禁用并说明原因。
- 可取消状态显示“取消任务”，点击后弹确认框。
- 模拟执行产物必须显示“演示兜底”标记。
- 任务详情首屏默认展示 Issue 摘要、AI 分析、当前计划和当前状态；完整日志和上下文可折叠。

### 5.6 审批中心页

页面目标：让审批人快速审核修改计划。

```text
+----------------------------------------------------------------------------------+
| 待审批列表 / 站内待办                                                           |
| - 任务名 | 风险等级 | 仓库 | 提交人 | 审批人 | 提交时间 | 催办状态 | 操作        |
+----------------------------------------------------------------------------------+
| 审批详情                                                                       |
| 左：计划摘要   中：文件范围   右：风险提示 / 阈值说明                          |
| 审批意见输入框                                                                  |
| [通过] [拒绝] [要求重写]                                                        |
| 审批历史时间线                                                                  |
+----------------------------------------------------------------------------------+
```

页面要求：

- 审批按钮必须明确且唯一。
- 审批按钮文案固定为“通过”“拒绝”“要求重写”。
- 风险提示要放在审批操作前。
- 历史审批记录要可追溯。
- 待审批任务按当前用户可审批范围展示。
- 项目默认审批人自动展示，未配置时提示管理员或研发负责人指定。
- 超过 24 小时未处理的任务显示“可催办”入口。
- 风险达到 `risk_threshold` 时显示强提示条，审批意见必填。
- 拒绝和要求重写时，审批意见必填。

### 5.7 任务回放页

页面目标：可视化展示 Agent 的完整执行过程。

```text
+----------------------------------------------------------------------------------+
| 左：任务时间线                | 右：步骤详情                                    |
| - 任务创建                    | - 当前步骤输入                                  |
| - Issue 拉取                  | - 当前步骤输出                                  |
| - RAG 索引 / 检索             | - 检索 Query / Top-K / 来源文件                 |
| - AI 分析                     | - 工具调用记录                                  |
| - 问题确认                    | - 用户回答                                      |
| - 计划生成                    | - 命令执行结果                                  |
| - 审批通过                    | - Diff / 测试 / PR 产物                        |
| - Diff 生成                   | - 演示兜底标记                                  |
| - 测试执行                    | - stdout / stderr / exit_code                   |
| - PR 描述生成                 | - 步骤备注                                      |
| - 重试 / 取消                 |                                                |
| - 完成 / 失败 / 已取消        |                                                |
+----------------------------------------------------------------------------------+
```

页面要求：

- 时间线必须支持折叠和定位。
- 每一步都要展示输入、输出和状态。
- 失败步骤必须可单独展开查看。
- RAG 检索记录必须展示文件路径、行号、Commit SHA 和相似度。
- 测试记录必须展示命令、耗时、退出码和日志。
- 模拟执行产物必须在时间线和详情中显示“演示兜底”标记。
- 取消任务要显示取消人、取消时间和取消前状态。

### 5.8 Diff 审核页

页面目标：审查代码修改内容。

```text
+----------------------------------------------------------------------------------+
| 顶部：文件统计 / 修改行数 / 风险 / 审核操作                                     |
+---------------------------+------------------------------------------------------+
| 左：文件列表              | 右：Diff 对比视图                                  |
| - file1.ts                | - 原始代码                                           |
| - file2.vue               | - 修改后代码                                         |
| - file3.py                | - 高亮新增 / 删除 / 修改                             |
+---------------------------+------------------------------------------------------+
| 底部：审阅意见输入 / 提交审阅意见 / 复制 Patch                                  |
+---------------------------+------------------------------------------------------+
```

页面要求：

- 左侧文件列表可筛选。
- 右侧 diff 视图默认打开当前文件。
- 需要支持代码块复制。
- 支持填写审阅意见并提交。
- 模拟 Diff 必须显示“演示兜底”标记，不可与真实 Diff 混淆。

### 5.9 索引管理页

页面目标：让管理员和研发负责人查看仓库索引状态，并触发创建、重建和重试。

```text
+----------------------------------------------------------------------------------+
| 顶部：索引管理 / 项目筛选 / 仓库筛选 / [创建索引] [重建索引] [重试]              |
+----------------------------------------------------------------------------------+
| 表格：仓库 | 分支 | Commit SHA | 状态 | 文件数 | 切片数 | 复用状态 | 失败原因 | 操作 |
+----------------------------------------------------------------------------------+
| 右侧详情抽屉                                                                     |
| - 索引版本                                                                       |
| - LlamaIndex 解析进度                                                            |
| - Milvus Collection                                                              |
| - 最近检索任务                                                                   |
| - 错误日志                                                                       |
+----------------------------------------------------------------------------------+
```

页面要求：

- 状态内部覆盖 `PENDING / SYNCING / PARSING / EMBEDDING / STORING / COMPLETED / FAILED`，界面统一显示对应中文状态。
- `COMPLETED` 且 Commit 匹配时显示“可复用”。
- 过期索引显示“仅可人工查看，不允许自动 Diff”。
- 失败索引显示失败原因和重试入口。
- 创建、重建、重试操作必须有确认弹窗和审计提示。

页面目标：配置 Gitee、模型、测试命令和安全策略。

```text
+----------------------------------------------------------------------------------+

+----------------------------------------------------------------------------------+
| 表单区                                                                           |

| - 默认审批人                                                                     |
| - 审批模式                                                                       |
| - 模型选择                                                                       |
+----------------------------------------------------------------------------------+
```

页面要求：

- 配置项按模块分组。
- 高风险配置项要有明显提示。
- 支持保存草稿和重置。
- Gitee Token 和模型 API Key 不回显明文，只显示别名、更新时间和可用状态。
- 密钥更新使用“重新填写”模式，保存前提示会写入审计记录。

## 6. 组件规范

### 6.1 通用组件

- 顶栏导航
- 左侧侧边栏
- 状态标签
- 风险标签
- 任务卡片
- 表格
- 抽屉面板
- 弹窗
- 时间线
- Diff 视图
- 空状态
- 加载态
- 错误态

### 6.2 关键组件规则

| 组件 | 规则 |
| --- | --- |
| 状态标签 | 使用 PRD `12.1.1 枚举中文展示` 的中文名，不直接显示英文枚举 |
| 风险标签 | 低 / 中 / 高 三档，不使用多余修饰 |
| 时间线 | 按时间倒序展示，支持展开细节 |
| Diff 视图 | 左右对比，默认按文件折叠 |
| 审批按钮 | 通过 / 拒绝 / 要求重写 三按钮固定位置 |
| 右侧抽屉 | 仅展示摘要，不塞太多操作 |
| 演示兜底标签 | 用于模拟 Diff、模拟测试摘要和模拟 PR 草稿，必须醒目但不遮挡正文 |
| 通知入口 | 顶栏铃铛和审批中心待办列表同步展示待审批数量 |
| 取消按钮 | 只在可取消状态显示，点击后必须二次确认 |

### 6.3 状态与颜色映射

| 类型 | 中文展示 | 建议颜色 |
| --- | --- | --- |
| 进行中 | 已创建 / Issue 已拉取 / 代码上下文已索引 / AI 分析完成 / 修改计划已生成 | 蓝色或信息色 |
| 待处理 | 等待人工审批 / 待回答 / 待处理 | 橙色或警告色 |
| 成功 | 审批通过 / Diff 已生成 / 测试完成 / PR 描述已生成 / 任务完成 / 索引完成 / 测试通过 | 绿色 |
| 失败 | 审批拒绝 / 任务失败 / 索引失败 / 测试失败 | 红色 |
| 取消 | 用户主动取消 | 灰色 |
| 兜底 | 演示兜底 | 紫色或深灰描边标签 |

### 6.4 风险提示规则

| 风险等级 | 展示方式 |
| --- | --- |
| 低风险 | 普通标签 |
| 中风险 | 黄色标签，审批页展示风险说明 |
| 高风险 | 红色强提示条，审批意见必填 |
| 达到 risk_threshold | 在审批中心、任务详情、Diff 审核页显示强提示 |

## 7. 状态规范

- 空状态
- 成功态
- 错误态
- 权限不足态

## 8. 交互规范

1. 创建任务后自动进入详情页。
2. 审批前不可执行 Diff 生成。
3. 任务回放页支持跳转到任意节点。
4. Diff 页支持文件切换。
5. 配置页修改后要有保存成功提示。
6. 失败任务要能快速看到失败原因。
7. 可取消状态显示“取消任务”，终态隐藏取消入口。
8. 拒绝和要求重写时，审批意见必填。
9. 高风险或达到风险阈值时，审批意见必填。
10. 已过期索引只能人工查看检索来源，不允许进入自动 Diff。
11. Token 和 API Key 只显示别名、更新时间和可用状态，不回显明文。
12. 模拟执行产物在任务详情、Diff 和回放中必须显示“演示兜底”标签。

## 9. 文案规范

文案风格要简洁、明确、偏企业工具：

- 用“创建任务”而不是“开始魔法”
- 用“修改计划”而不是“AI 想法”
- 用“审批通过”而不是“确认一下”
- 用“执行失败”而不是“出了一点小问题”
- 用“用户主动取消”而不是“停止了”
- 用“演示兜底”而不是“模拟结果”

## 10. 给 Stitch 的使用建议

如果把这份文档丢给 Stitch，建议按下面顺序生成：

1. 先生成整体 App Shell。
2. 再生成工作台首页和任务列表页。
3. 再生成创建任务页、任务详情页、审批中心和任务回放页。
4. 最后补 Diff 审核页、索引管理页和项目配置页。

这样 Stitch 更容易先建立统一布局，再做细节页面，不容易每页风格跑偏。
