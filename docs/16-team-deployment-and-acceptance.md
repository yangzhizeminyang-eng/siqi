# 团队版部署与验收文档

> 迁移说明：团队版部署、测试和验收清单已整理到 `team/05-team-deployment-acceptance.md`。本文保留为旧入口，避免历史引用失效。

## 1. 部署定位

团队版仍建议先采用单台云服务器部署，使用独立端口和独立环境变量与 MVP 隔离。

> **端口口径（以实际落地为准）**：下方 `8001/8002/8003` 是早期三阶段**规划**端口，
> 来自 `deploy/docker-compose.ports.example.yml`，**均未用于生产**。
> 实际落地的公网入口是：**团队版 `8080`、企业版 `8081`**（企业版生产再经宿主机 Nginx `80→308→443` 回代 `127.0.0.1:8081`）。
> 本地联调端口另有约定：团队版前端 `5177` / 后端 `8002`（见 `USER_GUIDE.md`）。

| 环境 | 早期规划端口 | 实际落地入口 |
| --- | --- | --- |
| MVP | `8001` | 本地开发 `5173`（前端）/ `8000`（后端） |
| 团队版 | `8002`（本地联调仍在用） | 生产 `8080`；本地联调 `5177` / `8002` |
| 企业版 | `8003`（**作废**） | 生产 `8081` → HTTPS `443` |

## 2. 环境隔离

| 资源 | 团队版建议 |
| --- | --- |
| 应用端口 | 生产 `8080`；本地联调 `8002` |
| 应用环境 | `APP_ENV=team` |
| MySQL 数据库 | `agent_team` |
| Redis DB | `1` |
| Milvus Collection 前缀 | `team` |
| 日志目录 | `logs/team` |

## 3. 部署检查项

- 团队版服务与 MVP 服务端口不冲突。
- 团队版使用独立数据库。
- 团队版 Redis 队列和 MVP 隔离。
- 团队版 Milvus Collection 前缀和 MVP 隔离。
- 团队版密钥不复用 MVP 示例配置。

## 4. 验收场景

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 多成员登录 | 使用 3 个不同账号登录 | 权限和可见任务不同 |
| 指定审批人 | 开发者创建任务并指定审批人 | 审批人收到待办 |
| 审批催办 | 待审批任务超过模拟时间 | 可触发催办并生成通知 |
| 评论协作 | 在任务详情新增评论并 @ 成员 | 被 @ 成员收到通知 |
| 权限拦截 | 观察者尝试审批 | 前端禁用，后端拒绝 |

## 5. 上线前清单

- 环境变量已填真实值。
- 默认审批人已配置。
- 团队成员和角色已初始化。
- 通知列表可用。
- 审计日志可查询。
